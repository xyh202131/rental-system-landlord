# 本地家具试摆

本轮实现方案 A、B：选择已有房间成果，在相同三维场景中放置已有家具并保存布局。试摆页集成在房东端同一个本地服务中，复用现有登录、账号权限、Spark / Three.js 预览与初始点控制。无需另启租客服务、配置跨端口 Cookie 或挂载另一份数据库。

## 使用

在项目目录运行 `npm run build`、`npm start`，打开 http://localhost:4317 并登录。

1. 在“重建样例”选择房间，点击“送入本地试摆”；成功重建预览也有此入口。左侧“家具试摆”可查看当前账号所有可用成果。
2. 点击家具库的“添加”，可重复添加同一种模型。点击布局列表选择对象，也可直接点选画面中的家具。
3. 使用位置、离地高度、旋转、比例控件调整；“点选落位”开启后可点参考平面放置，“聚焦家具”用于快速检查，“贴到地面”恢复参考高度。
4. 自动建议的地面可能不准确，可展开“调整参考地面”手动修改。参考网格可开关；“辅助透显家具”默认开启，优先显示家具以避免点云伪影遮挡，关闭后按原始场景深度显示。场景保留原有移动、转向、缩放、全屏和初始点。
5. 点击“保存布局”。只有显示“布局已保存到本机”才表示服务端保存成功。重新载入会询问是否放弃未保存改动，离开或刷新页面也会提示。保存失败保留当前调整；另一页面先保存时返回冲突，需显式重新载入。

布局、朝向与比例仅供视觉试摆。房间单位未知，参考地面来自剔除点云尾部后较低处的密集高度带；家具尺寸来自原材料中的估计值，模型采用 Y 轴向上并保持原始长宽高比例。未提供实测尺度标定、精确尺寸验证、碰撞检测或家具适配保证。

## 数据与接口

- `GET /api/furnishing/rooms`：返回当前账号可用房间及固定家具库。内置样例与私有导入优先使用本地 SPZ，其次 PLY；重建任务只列出当前账号 `SUCCEEDED` 且有可用模型地址的成果。
- `GET /api/furnishing/rooms/:roomId`：返回最小房间清单和当前模型版本的布局。清单只含名称、来源、模型地址、朝向、初始相机、版本和未标定状态，不包含证件、拍摄素材、内部备注或数据库路径。
- `PUT /api/furnishing/rooms/:roomId/layout`：提交 `sceneVersion`、当前 `revision`、`floorY` 和最多 20 个 `placements`。每个实例有独立 `id`、固定 `assetId`、`position[3]`、`rotationY` 和 `scale`。服务端验证数值、资产和版本，使用现有 CSRF / Origin 校验。
- `GET|HEAD /api/furnishing/furniture/:assetId/model.glb`：登录后按固定 ID 读取本地模型，支持字节范围；未开放数据目录。

布局写入现有 SQLite 的 `furnishing_layouts` 表，主键为账号、房间 ID、场景版本。场景版本包含资产身份、文件大小与修改时间，以及朝向；远端任务包含任务 ID、采集版本和模型路径，忽略临时签名查询参数。改变模型文件或朝向后不会自动套用旧布局；旧行保留以便原版本恢复。单独改名称或备注不清空布局。

三证 Mock 仍在用户中心，未通过时不能推进采集主线。查看已有房间及保存试摆属于预览工具，不生成、上传或提交拍摄任务。成功任务若只剩远端模型地址，查看仍需网络与有效地址；首轮使用本地样例和导入文件即可不依赖云端模型接口。

## 实现来源与本轮范围

房间与家具的同场景试摆、按高度归一化、手动摆位参考了第 8 组 [AholoHomeService](https://github.com/fengye1003/AholoHomeService/tree/23cfc195e7b0f643fa5b8cebafce536357a9cf94) 与压缩包 demo。当前接入使用现有 Three.js 场景，没有引入另一套 Aholo Viewer 对象、第三方全局目录状态、演示房源价格或发布复选框。布局改为按房间与模型版本保存。

本轮不接自动抓拍、外部尺寸估算、Lux3D 创建、USDZ / 真机 AR、租客市场或发布链路。
